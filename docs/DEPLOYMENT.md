### أول مدير
لا يمكن إنشاء مدير من الموقع. من محرر SQL (صلاحية الخدمة):
```sql
insert into public.user_roles (user_id, role)
select id, 'admin' from auth.users where email = 'ops@safeer.sa';
```
ثم يسجّل المدير دخوله ويُطلب منه تفعيل التحقق الثنائي (TOTP) قبل فتح غرفة العمليات. فعّل **MFA (TOTP)** في إعدادات Auth بالمشروع.

## 2. دوال الخادم (Edge Functions)
```bash
supabase functions deploy create-order payment-webhook track-click shipment-update commission-engine cms-upload shipping notify-dispatch
supabase secrets set ALLOWED_ORIGINS=https://safeer.sa MOYASAR_SECRET_KEY=… MOYASAR_WEBHOOK_SECRET=… \
  CRON_SECRET=… SHIPPING_WEBHOOK_SECRET=… CLICK_SALT=… \
  ADMIN_EMAILS=ops@safeer.sa SITE_URL=https://safeer.sa RESEND_API_KEY=… RESEND_FROM="Safeer <orders@safeer.sa>"
```
- **Moyasar**: أضف Webhook إلى `https://<project>.supabase.co/functions/v1/payment-webhook` مع نفس `secret_token`.
- **منصة تجميع الشحن** — راجع القسم 2.1 أدناه.
- **المهمة الليلية**: جدولة `commission-engine` يوميًا (Supabase Cron → HTTP POST مع `x-cron-secret`). تشغّل: محرك العمولات، وتحويل الطلبات الجماعية المنتهية دون اكتمال إلى «بانتظار قرار الإدارة»، وتنبيهات انتهاء وثائق المصانع وإعادة احتساب التوثيق.
- **الإشعارات بالبريد**: جدولة `notify-dispatch` كل 10 دقائق (مع `x-cron-secret`). ترسل الإشعارات غير المرسلة إلى أصحابها، وإشعارات الإدارة إلى `ADMIN_EMAILS`، والضيوف (مشاركو الطلب الجماعي بلا حساب) إلى بريدهم.

### 2.1 ربط منصة تجميع الشحن
تعمل المنصة الآن في **الوضع اليدوي** (`SHIPPING_PROVIDER=manual`، الافتراضي): الأسعار من تعرفة المنصة، ورقم التتبع وأحداث الشحنة يدخلها فريق المستودع من شاشة «الشحن واللوجستيات». بعد توقيع العقد:
1. اكتب مشغّل المجمّع في `supabase/functions/_shared/shipping-provider.ts` (الواجهة `ShippingDriver`: `rates` و`createLabel` و`track`)، أو استخدم المشغّل العام `http` إن كانت واجهة المجمّع تطابقه.
2. `supabase secrets set SHIPPING_PROVIDER=http SHIPPING_API_URL=… SHIPPING_API_KEY=… SHIPPING_WEBHOOK_SECRET=…`
3. في لوحة المجمّع، وجّه Webhook التتبع إلى `https://<project>.supabase.co/functions/v1/shipment-update` مع الترويسة `x-carrier-secret`. الصيغة: `{ "tracking_no": "…", "status": "in_transit|out_for_delivery|delivered|exception|returned", "occurred_at": "…", "description": "…", "location": "…" }`.
4. من «الشحن واللوجستيات» حوّل نمط الناقلين المتعاقد عليهم إلى «عبر المجمّع» (`carriers.mode = 'aggregator'`).

لا يتغير أي جدول أو شاشة أو سير عمل: تظهر الحالة «مربوط»، وتصدر البوليصة آليًا عند التجميع، وتصل الأحداث وتحرّك الطلبات (شُحن ← سُلّم ← نافذة الإرجاع ← العمولات وتسوية المصنع). يبقى الإدخال اليدوي متاحًا للتصحيح ويُسجَّل مصدره «يدوي».

> «التسليم» يبدأ عدّاد نافذة الإرجاع، فلا يُقبل آليًا إلا من المجمّع عبر السر المشترك.
- بعد أي تعديل على `src/config/platform.ts`: `npm run sync:shared` (اختبار التطابق يفشل إن نُسي).

## 4. ما يعمل على بيانات حقيقية عند تسجيل دخول فعلي

> التفصيل الكامل لكل شاشة في [`AUDIT_REPORT.md`](AUDIT_REPORT.md).
- **المتجر**: الأسعار وشرائح الجملة والمخزون والإتاحة تُقرأ من جدول `products` (نفس مصدر تسعير الخادم).
- **المشتري**: طلباتي، عروض الأسعار (مقارنة أفضل سعر وأسرع تجهيز + قبول بخطة دفعات)، صفقات الجملة ودفعاتها.
- **السفير**: المحفظة (معلّقة / قابلة للسحب / قيد الصرف / مصروفة) وطلب السحب، والطلبات المنسوبة وعمولاتها.
- **المصنع**: الطلبات الفرعية والمبالغ المحتجزة والمستحقة، وطلبات عروض الأسعار وإرسال العرض، ووثائق التوثيق، وصور المنتجات، والتسليم للمستودع.
- **الإدارة**: دفتر التسويات من الطلبات المدفوعة فعلًا، طابور صرف العمولات، الحسابات، الإعدادات التجارية، المحتوى، عمليات المستودعات، الشحن والمجمّع، الطلبات الجماعية، التوثيق.
- **الجميع**: جرس الإشعارات في الشريط العلوي.
- بقية الشاشات تظهر مع تنبيه صريح «بيانات توضيحية» حتى ربطها.

## 5. قبل الإطلاق — ما يحتاج قرارًا أو عملًا يدويًا
1. **الكتالوج** صار في قاعدة البيانات؛ أي منتج جديد يُضاف إلى `products` ويُفعَّل (`active = true`) بعد المراجعة. الصور والأوصاف الطويلة ما زالت من ملفات الواجهة.
2. **أسعار الشحن**: أسعار مناطق الشحن السريع تقديرية. استبدلها بعقد منصة التجميع من «الإعدادات التجارية ← الشحن».
3. **أسعار الصرف**: حدّثها أسبوعيًا من «اللغات والعملات».
4. **«فاتورة» (ZATCA)**: الترقيم والتجزئة جاهزان؛ التوقيع الإلكتروني ورمز QR والتقديم للهيئة يحتاجان شهادة CSID وتكاملًا مع واجهة الهيئة.
5. **نفاذ**: التحقق ما زال يدويًا من الإدارة؛ الربط يحتاج اتفاقية تكامل.
6. **الترجمة**: الأردو والإندونيسية تغطيان التنقل والتذييل والرئيسية والمتجر وصفحة المنتج والسلة والدفع والأكواد. الصفحات القانونية والأسئلة ولوحات التحكم تظهر بالإنجليزية حتى تُترجم ترجمة احترافية (والنص القانوني يحتاج مراجعة مختص).
7. **الشاشات التوضيحية المتبقية** (التحليلات، المخزون، العقود، الرسائل…) تحتاج ربطًا تدريجيًا؛ الجداول الأساسية والسياسات جاهزة.
